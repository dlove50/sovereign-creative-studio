# Sovereign UI upgrade — 2026-10-10

## Outcome

Sovereign now has a consistent responsive shell, a persisted three-state motion preference, strengthened shared UI primitives, and polished home, library, status, and creation surfaces. Existing routes, API contracts, workflow payloads, authentication, credits, and backend behavior were preserved.

The production frontend was rebuilt into `.next-cinematic-fixed`, launched on port 3000, and verified against the existing backend on port 8002.

## Animation regression root cause

Motion had several independent authorities. Some components queried the operating system directly, while Lenis, GSAP, canvas effects, page transitions, and decorative effects managed their own lifecycles. That made behavior inconsistent after navigation and preference changes and made an intentional reduced-motion state look like a regression.

The repair introduces one persisted preference contract:

- `Follow system` (default): respects the operating-system reduced-motion setting.
- `Always on`: enables interface motion even when the operating system requests reduced motion.
- `Off`: disables non-essential motion.

`MotionProvider` now resolves that preference once and supplies the same state to Lenis, GSAP hooks, canvas effects, count-up text, page transitions, and decorative motion. Preference changes clean up and recreate runtime work without a reload.

## Design decisions

- Retained Sovereign's charcoal, cyan, violet, Plus Jakarta Sans, and Lucide identity.
- Strengthened semantic surface, elevation, focus, spacing, content-width, and motion tokens.
- Kept one obvious primary action per major surface.
- Standardized loading, empty, failure, and success language and semantics.
- Made navigation usable by keyboard, pointer, and touch; interactive targets are at least 44px where tested.
- Preserved every route and workflow rather than replacing product behavior with a visual prototype.

## Changed surfaces

- Application shell, desktop rail, mobile navigation, top bar, account menu, and motion selector.
- Home/setup experience and director template presentation.
- Gallery, Projects, Avatars, and Apps libraries.
- Video Agent and Music Lab creation workflows.
- Credits, Admin Dashboard, and Status surfaces.
- Shared buttons, cards, inputs, textareas, badges, skeletons, empty/error states, and page headers.

## Independent final review

A fresh read-only whole-branch review found no Critical issues and four reproduced findings. The bounded fix pass addressed all four:

- Portaled mobile navigation to the document body so the fixed drawer covers the full viewport instead of the blurred header's containing block.
- Enabled GSAP context reversion on motion-preference updates so pending reveals stop and content returns to its visible resting state.
- Restored a deliberate keyboard path from both Create and Avatar rail controls into their flyout links, while retaining native synthetic activation.
- Redrew the Music Lab's static spectrum after resize and visual-input changes when motion is Off.

## Known limitations

- Existing `<img>` optimization warnings and two pre-existing hook dependency warnings remain outside this UI-only scope.
- Live Quick Chain generation requires its selected ComfyUI image model to be installed and ready. The interface reports that generation is unavailable rather than falsely advancing.
- Generated screenshot artifacts are intentionally test output rather than source-controlled binaries.

## Rollback

All work is isolated on branch `ui-upgrade-2026-10` in named-file commits and was not pushed. To roll back safely, stop the frontend on port 3000, switch to the prior branch/commit, rebuild `.next-cinematic-fixed` with `BACKEND_ORIGIN=http://127.0.0.1:8002`, and run `C:\Sovereign\start-sovereign.ps1`. Do not remove backend data or storage; this upgrade did not migrate either.
